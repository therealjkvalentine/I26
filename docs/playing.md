# Playing I26

Details for players. The [README](../README.md) has the features and a short install guide; [jumps.md](jumps.md) explains
how a car flies off a ramp and lands (T05's canyon worked through).

## System requirements

- Windows 10 or later, or a 64-bit Linux (x86_64 or ARM64), with your own copy of Interstate '76 (and the Nitro Pack for its
  content), or macOS (one app for Apple silicon and Intel; signed ad hoc, not notarized by Apple, and so far
  tried on one Apple-silicon Mac with macOS 26, not on an Intel Mac).
- A GPU with a Vulkan 1.2 driver (or, on Windows, Direct3D 12) for the intended look. A machine with neither falls back to
  OpenGL (Godot's Compatibility renderer): the game runs, with no SSAO and some small differences; it says so once in the
  shell and in the log (see [docs/compatibility-renderer.md](compatibility-renderer.md)). If the picture is wrong on your
  machine, Graphic Detail's **Renderer** row switches between Vulkan, Direct3D 12 (Windows) and OpenGL at the next start.
  Auto says which one it runs on ("Auto (Vulkan)"); on Windows with an AMD card it is Direct3D 12 from the second start.

## Installing and starting

1. Download the release zip for your system (`i26-<version>-windows.zip`, `-linux.zip`, `-linux-arm64.zip` or
   `-macos.zip`) from the GitHub releases page.
2. Run `i26.exe` (Windows) or `i26.x86_64` (Linux) from inside the unpacked `i26-<version>` folder, or open `I26.app`
   there (macOS). Nothing needs installing. On macOS, first clear the quarantine flag the browser put on the download, in
   Terminal: `xattr -dr com.apple.quarantine i26-<version>`. Otherwise macOS stops the app (it is not notarized), and an
   app opened while it still has the flag runs from a temporary copy elsewhere (App Translocation), where the `i76` and
   `nitro` folders beside it are not found. Give it the game in one of these ways; if
   it cannot find one it says so and lists the places it looked.
   - **Installed GOG game (including GOG Galaxy):** either copy your game folder into the I26 folder as `i76` (and
     `nitro` for the Nitro Pack), or unpack the I26 folder into your game's folder (only that game is found then).
   - **GOG offline installers:** put `setup_*.exe` next to `i26.exe` (or in the folder above it). I26 unpacks it into
     `i76` / `nitro` itself, once (about 465 MB for Interstate '76, 290 MB for the Nitro Pack; the launchers, most DLLs
     and GOG Galaxy files are left out; the game's own executable is kept, as I26 reads the computer drivers' tactics
     from it). You can also choose **Use a GOG installer...** on the "could not find" screen, or run
     `i26 -- --from-installer setup_interstate76_2.1.0.17.exe [--to DIR]`.
   - **Anywhere else:** a shortcut with `-- --install "C:\path\to\game"`.
   - **Updating I26:** move your `i76` and `nitro` folders into the new version's folder (or keep them in the local user
     folder, which every version checks).

Extraction goes into `i76` / `nitro` inside the I26 folder if that folder is writable, the subfolder is absent, empty or
I26's own earlier extraction, and there is space; otherwise into `i76` / `nitro` in the local user folder
(`~/.local/share/I26/` on Linux, `%LOCALAPPDATA%\I26\` on Windows). I26 never unpacks into a folder that holds
something else. Those folders hold any valid install, so a game folder copied in by hand works the same. Wine is not
needed. The small "GOG Galaxy" downloader `.exe` holds no game data and cannot be used; installers split into
`setup_...-1.bin` parts need the parts next to the `.exe`.

**Which game starts.** At start I26 collects the games it can run: installs (Interstate '76 and the Nitro Pack) and GOG
offline installers (`setup_interstate76_*.exe`, `setup_interstate76_nitro_pack_*.exe`) lying next to the executable, in
its parent folder or in the local user folder (installs: see above); a game counts once, its install preferred over its installer. One game starts
at once (an installer is unpacked first, with a progress bar). Both: a chooser shows the two games' main-menu logos side
by side (mouse, Left/Right and Enter, or the pad's D-pad and A; Esc quits); the last choice is preselected, and a game
that is still an installer is unpacked when you pick it (Cancel returns to the chooser). The main menu's Esc options have
**Switch Game** to come back to it (`--choose-game` on the command line). `--install`, `I76_INSTALL`, `--mission` and
network options skip the chooser.

**The Nitro Pack from Interstate '76's menu.** With both games found, the main menu's **MELEE** > **AUTO MELEE** row has
**NITRO**, between SCENARIO and INSTANT MELEE. It goes straight to the Nitro Pack's character choice (Taurus, Jade, Skeeter, the fourth once the first three are done, Training), in its own art;
a character opens its scenario form, and ENTER AREA plays the mission as the Nitro Pack's own menu does (its rules, music,
voices, cars and progress; Play Options there are the Nitro Pack's own). BACK on the character choice, or the end of a
mission, brings you back to Interstate '76's main menu with MELEE > AUTO MELEE open. No restart: the window changes game as Switch Game
does. With only one of the games, the menus are as before.

**Roguetrip.** The main menu's **MELEE** row has **ROGUETRIP** after AUTO MELEE (Interstate '76 only): a run of four generated
jobs on the trip's maps, one car, its damage carried from job to job (docs/remix-missions.md "Roguetrip"). It opens a car pick
(the scenario form), ENTER AREA asks for a run number (blank for a new one; the same number gives the same jobs), then a map of
the region offers the first jobs. Esc steps back one screen at a time, to MELEE. A run in progress is kept between sessions:
ROGUETRIP goes straight back to it. One-off generated jobs stay on the SCENARIO form as RANDOM JOB. The main menu also answers
the arrow keys and Enter (as a pad's D-pad and A). The gangs drive cars of the game near your own: the better your car's engine,
suspension, brakes and guns (as the garage leaves them after each job), the better the cars a job sets on you, and the better the parts
their wrecks leave in FIELD SALVAGE (in the condition the fight left them, mostly battered: queue the good ones for repair). From the
second job a lead car a step above the rest carries something at or above your own in some slot; win a job at challenge 1.0 or more and
that part is in the field too, never in the red.

**Roguetrip in co-op.** Host it as any co-op game: MELEE > MULTI MELEE > HOST, the MELEE / CO-OP button to CO-OP, then ROGUETRIP, the
last row of AREA OF PLAY, and BROADCAST GAME. The others join from the roster as for any co-op game and pick their cars in the lobby
(everyone on the same build of I26: a game that cannot build the jobs is told so at the join). In the lobby the host's **ROUTE MAP**
(or R) opens the run's map of the region: pick one of the offers (Up, Down, 1-3 or a ring), Enter goes back to the lobby, START plays
it. Everyone else's ROUTE MAP shows the same map, the host's pick ringed in red, as it changes. Each player builds the job on their own
machine from the host's numbers; the enemies grow with the crew (two players about 1.75 times a single player's job, four 3.25). Your
car's damage carries from job to job as long as you keep the same car. Killed in a job, you are out of it (no respawn: the death card
says so) and back for the next with your car patched to half armour; the run ends only when the whole crew is killed. A failed job
otherwise is a bust (the next a step harder). After each job everyone is back in the lobby on the debrief; the host's CONTINUE (or
Enter) goes on to the next choice: there is no field salvage or garage in co-op, a won job patches 30 % armour onto each car still
running and reloads its guns. The gangs' cars match the crew's average car. The host keeps the run (user://remix/coop-run.yaml): host ROGUETRIP again and the run goes on, with the
same or fewer players. Players who leave mid-job do not end it; new players can join between jobs in the lobby.

The install is looked for in this order: `--install DIR`, the `I76_INSTALL` environment variable, the executable's
folder and its parent, `i76` and `nitro` inside the executable's folder, `i76` and `nitro` in the local user folder, then
GOG offline installers (in the executable's folder, its parent and the local user folder). I26 remembers no install
location between runs; an old `[install]` entry in `settings.cfg` is ignored.

**Settings and saves** live in your user folder, never in the game folder: `~/.local/share/I26/` on Linux,
`%APPDATA%\I26\` on Windows. Delete it to start from scratch. The first run copies
the settings and saves of the older "Interstate '76 (Godot)" folder if there is one.

**Bringing in saves.** Load Bookmark is the original's sheet plus a Delete button. Two tools for bringing bookmarks in are
on the Developer Tools panel of the main menu instead (Ctrl+F2 or Ctrl+` there, with `developer=true` under `[port]` in
shell.cfg or `--dev`; Interstate '76 only, the Nitro Pack has no trip):

- **Import Saves** lists the bookmarks the original game saved in its folder (`savegame.dir` and the `saveNNN.cmp`
  files; on Windows also their copy in `%LOCALAPPDATA%\VirtualStore` when the game sits under Program Files), as the
  original's Load board lists them, and Import turns each into an I26 bookmark with the same name and scene. The car
  comes with it: the body, paint, armour and chassis, every part fitted, in the van, in the repair order or left in
  Field Salvage, each in the condition it was saved in. A part is fitted only where the original's garage would show it
  fitted, and weapons past the garage's eleventh go to Field Salvage, as the original does on loading. Importing again
  skips the bookmarks already imported. The original's files are only read.
- **All Scenes** makes a bookmark for every scene of the trip, "Scene N. <the mission's title>", each at the start of
  its scene in that mission's own stock car, so a fresh install can start any scene without a save. It asks first and
  never overwrites a bookmark of the same name.

Both end on Load Bookmark with the new bookmarks listed.

**Bookmark names.** A bookmark is listed under the name you type when you save it. Save it without one (Enter on the
empty field, as the original allows) and Load Bookmark lists it by its mission, "Scene 5. Save Taurus", where the original
shows "Scene 5. " alone; bookmarks you saved before read the same way.

**Update check.** At every start I26 asks GitHub (one request, nothing about you or your machine is sent) whether a newer release exists and, if so, shows "version X available" under the version in the corner of the chooser and the main menu; click it to open the release page. Options > Play Options > Check for Updates (near the end of the sheet's scrolling list) turns it off, and then nothing is requested. A build run from source never asks.

**Checkpoints.** With Play Options' Checkpoints on, a trip mission keeps a checkpoint once its intro is over and at each
objective done, and Retry from Checkpoint (the Esc menu's Abort Mission pad, and the menu after a failure) starts again
from the latest. Beside it, **Save Bookmark** adds a new "Scene N. <the mission's title> - Checkpoint" row to Load Bookmark: your trip as the
mission started, with that checkpoint. Loading it starts the mission and puts you back at the checkpoint, with the car,
its weapons and damage and the mission as they were; your current trip is not changed by saving one. A checkpoint
bookmark is for this version of I26: after an update the bookmark still loads, and the mission starts from its beginning
(a note says so).

**New Game Plus.** When you win Scene 17, the menu after the credits offers a New Game Plus save. YES adds "Scene 1. New
Game Plus" to Load Bookmark: your car with its parts, the van's stock and the repair order, back at Scene 1 on a harder
road. It does not start anything or touch your other bookmarks; load it when you like. NO costs nothing: NEW TRIP asks
from then on (NO there starts over as the original does, in the stock car; YES drives New Game Plus at once in your car;
Esc leaves things as they were). In New Game Plus every enemy car the mission is not about comes with a copy of itself,
every enemy drives and shoots one skill step better, and the field salvage lets through parts four scenes ahead of where
you are. The cars a scene fails on losing (the van in Scene 16) take less damage, as in co-op with Extra Enemies, and a
boss stays one of a kind. Win Scene 17 again for the New Game Plus 2 save (two copies, two steps), and once more for New
Game Plus 3, the last. The main menu's TRIP banner says which one you are on; bookmarks remember theirs, and a checkpoint
made in one only resumes in the same one. The story plays as before (Scene 4's dream, Scene 17's borrowed cars). It is
single player only, and a win with cheats on gives no New Game Plus save, as it gives no salvage and no next scene.

**Log file.** Off by default, so it cannot grow. For a bug report, start the game once with `--log` (or the environment
variable `I76_LOG=1`) and attach `logs/godot.log` from the user folder (the last three runs' logs are kept as
`logs/godot<date>.log`); `log_file = true` under `[port]` in shell.cfg (or the Developer panel's Settings) keeps it on for every start (it had a Graphic Detail row until round 5). Logs from older versions
stay where they are and can be deleted.

**Reporting a bug.** The Esc menu's Options Menu has a **Report a Bug** row, near the foot of the pad (Ctrl+F11 does the same, on the pad or in play). It
writes a folder `bug-reports/<date-time>/` in your user folder and zips it beside the folder as `i26-bug-<date-time>.zip`
(under 5 MB as a rule); the pad shows the name, with **Open Folder** to show it in your file browser. Drag the zip into Discord
or a GitHub issue, with a line on what went wrong. It holds `report.txt` (the build and network protocol, your system and
renderer, the game, mission, simulation tick and car with its place and heading, your settings in short, the texture packs'
versions, a network game's roster by car), `state.sav` (a save state of that moment, which a developer can load and step
through, since the simulation is deterministic), `shell.cfg` (a copy of your settings), `screenshot.png` (the frame you saw as
the menu opened, no wider than 1920), `log.txt` (the last 400 lines of the game's own output, kept in memory whether or not the
log file is on) and `inputs.csv` (the last ten seconds of your keys and stick; `[port] bug_report_inputs=false` leaves it out).
Nothing personal goes in: the user folder, your home folder, your user name, your machine's name and the install's and the
program's folders are blanked wherever they would appear; a network game's player names and addresses are left out. In a
network game the report is written while the game runs on, so the frame may hitch for a moment. A developer reopens the
report's moment with `--bug-report-open <zip>` ([docs/dev-hooks.md](dev-hooks.md)).

**Custom maps.** Install community maps as for the original game: unzip them into the game's own folders. For the
Nitro Pack, the map files (`.cbt` combat, `.rac` race, `.cf2`/`.cf3`/`.cf4` capture the flag, with their `.ter`) go
into `miss16` (and `miss8`), or into `addon`; for Interstate '76, a level's `.lvl` and `.ter` go into `addon`. Car
variants and parts (`.vcf`, `.wdf`) go into `addon`. They appear in the melee and network arena lists under their own
names, Nitro's by game type. In a network game every player needs the same map: a player whose copy is missing or
different is told so when joining. Maps made for the 1997 release (`.lvl` files without a horizon) and maps whose
terrain file is misnamed or short play too, and so do Interstate '76 `.lvl` maps dropped into the Nitro Pack's folders
(as combat arenas). A map left in a folder of its own inside `addon` (as Windows' "Extract All" does) is found too. A
map whose terrain file is missing is still listed, as in the original, but choosing it brings you back to the form
with a note naming the file. Interstate '82 maps (`.msa`)
are for another game and are not listed.

**Graphic Detail.** The main menu's sheet (Options) and the Esc menu's pad. The original has one sheet of rows; here the sheet holds **1997 Mode** (the switch between the two looks, which decides which of the pages' rows apply), **Quality** (a preset over the costly rows, below) and under a blank line four entries, **Display...**, **World...**, **Car & Cockpit...** and **Effects...** (each entry's tooltip lists what its page holds), the frame-rate line, Reset, Done and Cancel. Every other row, the original's too, is on the page it belongs to, by what it changes, the original's rows leading their pages in the original's order and words; a page is closed with Back (or Esc). Done and Cancel on any of them keep or undo everything changed since Graphic Detail was opened. Reset on a page puts back that page's rows; Reset on the sheet puts back 1997 Mode and every page's (the original's rows and the bytes no row shows to the original's default profile, as its Reset did, and every port row to its default). Every row has its own ruled line at the original's spacing and every page fits its sheet without scrolling, with the frame-rate line under a blank line.

**Quality.** Graphic Detail's second row on the sheet (the main menu's and the Esc menu's) is a preset over the modern look's costly rows, as modern games put an overall quality setting at the top of their graphics settings. Choosing **Original**, **Balanced\***, **High\*** or **Ultra\*** sets each of the rows below as stepping it by hand would, at once; when the rows match none of them it reads **Custom\***, and a click from there goes to Original. Nothing of its own is saved: it is read back from the rows, so Reset on the sheet (every row to its default) shows Balanced. The frame-rate line at the foot of the sheet follows the choice. Original is the original game's look in the modern renderer; Balanced is a first start's defaults; High and Ultra are for a strong graphics card (Ultra close to a 200 % supersampled setup). It leaves alone the window and monitor rows, Field of View, VSync, Max FPS, Menu Width, 1997 Mode and the rows that are taste rather than cost (Terrain Detail, Mirrors, Mirror Haze, Hood Gloss, Ext. Instrum. Disp., Radar Sweep, 1997 Palette Grade, Crash Blur, Motion Blur, Clouds, Shimmer Strength, 3D Garage). High's Mirror Rate is Smooth 1/2 (Half's draws, each mirror's picture moved with the car's turn between them); both High and Ultra draw the mirrors with SMAA (Ultra's view is SMAA too, so As View would draw the same, but would change with the Anti-Aliasing row).

A texture size takes the largest the installed packs offer up to it (8x with only the 4x pack is 4x); with no pack the texture rows are not shown and the preset leaves them out. The 1997 look draws none of these rows.

**When a row applies.** Every row's tooltip ends by saying when it takes effect: "Applies at once" (in a mission, on resuming; on the main menu, from the next mission, which is the next time the 3D view is drawn), "From the next mission" (1997 Mode; Car & Dash Textures between 4x and 8x) or "From the next start" (Renderer, whose value reads `(restart)`, e.g. `OpenGL (restart)`, while a choice waits for the next start). Tooltips also carry the words players search for: FOV, draw distance, frame cap, HUD panels, SSAO, SSR, bloom, gamma, foliage.

**Mirrors.** Graphic Detail's **Mirrors** row (the original's Rear Mirror row, with the port's door mirrors in it) sets which mirrors show the view behind: **All** (the default) the rear-view mirror and, in the modern look, the glass of each door mirror the car has (the Piranha's two, the CC cars' left one), **Rear + Left** the rear mirror and the driver's door mirror (the right one stays as the original paints it), **Rear** the rear mirror alone (the door mirrors the original's painted glass), **Off** no mirror. It is the rear mirror's mode (the original's Off, Low or High: Rear and the others turn it on at High; a Low in the file shows as on and is kept until the row is changed; the ` key still cycles it in play) and `[port] side_mirrors` (`off`, `left`, `auto`; `on`, set by hand, shows as All and stays until the row is changed). A file with the rear mirror off and the door mirrors on shows Off, which is what it draws (no mirror is drawn with the rear one off), and is left as it is until the row is changed. The door mirrors' glass is rounded inside its straight housing (`side_mirror_round`, 30 % of its shorter side; 0 for the glass's own corners). What each costs, in frames a second (3440x1440 from the cockpit, the playtest settings with Shadow Detail High, VSync off and Max FPS Unlimited, a GTX 1080 Ti at 180 W; measured, the median of 2 or 3 runs on a machine other work was also using, so the spread is wide; in brackets what the graphics card alone could draw, 1000 over its milliseconds): T01 Off 102 (146), Rear 95 (130), Rear + Left 83 (119), All 84 (121), All with Mirror Rate Full 73 (101); T05 Off 70 (116), Rear 62 (105), Rear + Left 57 (97), All 49 (98), All with Full 37 (84). Looking ahead the Piranha's right glass is out of view, so All costs what Rear + Left does; most of a door mirror's cost is the processor's (its camera's scene pass), so a fast processor loses less of it. Whatever the row, a mirror whose glass is out of your view is not drawn that frame: looking ahead at a 21:9 window with Field of View Monitor the Piranha's right glass lies 72 to 78 degrees to the right, past the view's 61, so it costs nothing until you look right, and the left one, then the only side drawn, is drawn every second frame instead of every fourth; a glass coming into view is drawn in the frame it appears. The rear mirror is left out the same way when you look away from it (out of the left window, or back), unless the 2D dash shows it. All and Rear + Left cost the same as the drawing before (one side mirror's picture every second frame: about 0.7 ms of graphics time a frame at 3440x1440, 1.4 ms a picture); Rear saves that. The 1997 look keeps the original's painted door mirrors whatever the row says (All and Rear + Left are its Rear).

**Mirror Rate.** Graphic Detail's Car & Cockpit page has **Mirror Rate** (`[port] mirror_rate`): how often the modern look's mirrors are drawn. **Alternate** (the default, `alternate`) draws the rear mirror every second frame, as the original does, and the side mirrors in turn on those frames, each every fourth frame, or every second when the other is out of view or off (Side Mirrors Left); **Half** (`half`) draws every mirror every second frame, both side mirrors on the same frame; **Full** (`full`) draws every mirror every frame, the smoothest picture in them when something passes you. Measured at 3440x1440 (T01 in the cockpit, the playtest settings, a quiet machine, n = 3, graphics ms and fps): Both 8.18 and 95 under Alternate, 8.16 and 94 under Half, 9.66 and 84 under Full; Left 8.18, 8.17, 9.62; Off (the rear mirror alone) 7.43, 7.42, 8.13. T05's start and pass (60 s): Both 9.86 and 70, 9.88 and 71, 11.59 and 64; Off 9.13 and 80, 9.12 and 80, 10.02 and 74; main before this row 9.83 and 72. Half and Alternate draw the same whenever one side is in view, which looking ahead is always (the Piranha's right glass is out of view, the CC cars have none); they differ only with both door mirrors in view at once. The 1997 look draws its mirror every second frame whatever the row says.

**Mirror Rate: Smooth.** Mirror Rate also has **Smooth 1/2**, **Smooth 1/3** and **Smooth 1/4** (`smooth2`, `smooth3`, `smooth4`; the port's own, marked \*): each mirror is drawn only every second, third or fourth frame, the three cameras in turn (at 1/3 one a frame: rear, left, right; at 1/2 the rear, then both sides), and on the frames between, its glass shows its last picture moved for how the car has turned since, as a VR headset's timewarp does. The render is drawn a little wider and taller than the glass shows (5 % across and 2.5 % up for each frame between draws), so a turn brings in picture that was drawn; past that the edge is stretched. The scenery then keeps up with a hard turn although it is drawn at a third or a quarter of the rate; what does not follow is anything that moves itself: a car behind you, smoke, the dust of your wheels, which update at the lower rate (at 60 fps and 1/4 that is 15 times a second, about the original's mirror at 30). Measured against Full on the same frames (the Piranha at speed in M01, 1920x1080, mean difference of the glass's pixels, 0 to 255): in a hard turn Alternate 5.0 on the rear glass and 4.0 on the left door glass, Smooth 1/3 1.9 and 2.0, Smooth 1/4 1.1 and 2.3 (the rear 2.1 re-projected for the turn alone), and the 1/4 schedule without any re-projection 9.8 and 8.5; on a straight at 30 m/s every rate is under 0.7 (Alternate 0.35 and 0.5, Smooth 1/4 0.1 and 0.7). The rear mirror is re-projected for the car's move as well as its turn, from its render's depth (a small compute pass copies it after each draw); the door mirrors for the turn alone, with the car's own flank (all of their picture nearer than 5 m) held where it was drawn and the gap a turn opens beside it filled from the flank's edge, as re-projecting their move put the ground beside the flank wrong. What it saves: at 1/3 the three cameras draw one picture a frame between them, as Alternate does (the rear every second frame, each side every fourth), so it costs about what Alternate does (the renders are about 10 % larger for the overscan) with the side mirrors kept up to date three times as often; 1/4 draws a quarter fewer pictures than Alternate, 1/2 half again more. Each mirror's picture at Full was 0.6 ms of graphics time at 3440x1440 with AA 8x and Render Scale 200 % (docs/perf/costs.md); the re-projection itself is a few texture reads in the glass's own shader, and the depth copy a compute pass over the 1024x256 or 512x256 render. (Not yet benchmarked as fps on the playtest machine.)

**Radar Sweep.** Car & Cockpit's **Radar Sweep** (`[port] radar_sweep`, shown with a texture pack) says how the cockpit radar's beam moves in the modern look. **Stepped** (the default; not written) is the original's: 30 painted frames, the beam 12 degrees further each, swapped every 0.2 s (a turn in 6 s, clockwise), and with a target held the lock cone on the frame nearest below the target's bearing, so it points up to 12 degrees off. **Smooth** (`smooth`) draws the beam on the graphics card every frame you see, at the same 60 degrees a second on the same clock, so it is exactly where the stepped frame puts it each time a step falls and turns evenly between; its afterglow fades behind it, and a held target's cone points straight at the target, swinging onto it from the beam and following it as it moves. Pauses stop it as they stop the stepped sweep; the pings, the blips' fading, the contact lamp and the range plate step and light exactly as before. It needs a pack whose radar has the sweep's layers (`zrads_face`, `zrads_grid`, `zrads.json`, written by `tools/radar-redraw.py` with the frames: docs/hd-textures.md); with an older pack, without a pack, in the 1997 look, on the OpenGL renderer, with the radar off and while the weapon camera shows in the screen the radar is the stepped frames whatever the row says. It costs nothing measurable, and saves the stepped frames' uploads (each step sends the changed part of a 2048x1024 frame at 8x).

**Mirror Haze.** Car & Cockpit's **Mirror Haze** (`[port] mirror_haze`) gives the modern look's mirror glass a touch of milkiness, as no mirror is perfect or perfectly clean, so the view in it does not look exactly like the landscape through the windscreen: a flat veil the same over the whole glass (its blacks lifted and its contrast lowered by a few per cent toward a pale warm grey) and the slightest softening of the picture; no gradient, smudge or dirt. **Low** (the default; `low`, not written) is barely seen, **Med** (`med`) about twice that, **High** (`high`) about three times, **Off** (`off`) the clear glass as before; the first release's words read forward (`slight` as Low, `more` as High). It is in the glass's own shader (a few more samples of the mirror's picture), so it costs nothing measurable and Off nothing at all; the 1997 look's mirror is the original's and never hazed. The Haze row's distance haze (above) is a different thing and already shows in the mirrors as in the main view: the mirror cameras draw the same haze pass at the full mirror reach (Mirror Range Full, the modern look's default); at the original's 100 m nothing in them is far enough for it.

**Mirror AA.** Car & Cockpit's **Mirror AA** (`[port] mirror_aa`) anti-aliases the mirrors' own pictures, which the Anti-Aliasing row never reached: each mirror is drawn by a picture of its own (the rear mirror's render and the door mirrors' cameras), and such a picture takes no anti-aliasing from the main view, so the mirrors have always been drawn without any. **Off** (the default; not written) is that. **2x**, **4x** and **8x** (`2x`, `4x`, `8x`) are MSAA in the mirrors' renders, **SMAA** (`smaa`) the edge filter the Anti-Aliasing row offers, run on each mirror picture after it is drawn (it also smooths what MSAA leaves: thin branches, poles, the horizon's cut-outs), **2x+SMAA** (`2x+smaa`) both, **As View** (`view`) whatever the Anti-Aliasing row has. It works with Mirror Rate's Smooth values and with Mirror Haze. Cost, measured on an RTX 5090 at 3440x1440 (a first start's settings, T01's start, one short run each): the mirrors themselves (Alternate) are about 9 % of the frame at those settings; 2x adds about 2 %, 8x about 9 % (8x in three small pictures costs about as much as the mirrors' drawing itself); SMAA works on pictures a tenth the size of the main view's, so it costs a tenth of the Anti-Aliasing row's SMAA (estimated, not measured). The 1997 look's mirror is the original's and never anti-aliased.

**Tooltips.** Every row of every menu has a tooltip: rest the pointer on a row for half a second and a small box beside it says what the setting does and, where it matters, what it costs; with the pad or the keys the box appears beside the selected row. It goes when the pointer leaves the row or a click changes it, and it stays on the screen whatever the window's shape. That covers Graphic Detail and Advanced, Play Options, Audio Control, Controls, Mouse Options, the key map, the host forms, the Esc menu's pads and the Developer panel (the panel's are Godot's own tooltips, by the pointer only). Graphic Detail's give each costly row's share of a full-detail frame (everything on, the T01 start, 3440x1440, a GTX 1080 Ti: docs/perf/costs.md): Ambient Occlusion about 29 %, Mirrors up to 17 % for the rear mirror, Anti-Aliasing 12 % at 4x and 9 % at 2x, Shadow Detail 8 %, Terrain Detail 6 %, Vegetation 4 % at High, Visibility Range under 3 % (and some 800 draw calls), the textures no frame time (video memory and loading); in the 1997 look the modern look's rows say they cost nothing there.

**Equipment tooltips.** The garage's part lists explain their parts the same way: rest the pointer (or the pad's focus) on a part in BUILD AND REPAIR, its pickers, the CAR / VAN INVENTORY, FIELD SALVAGE, the chassis forms (2D and 3D) or the melee and scenario forms' car panel, and a box beside the row says in two lines what the part does in the game and its numbers: an engine's drive force against the base engine, a suspension's cornering, a tyre's grip, a weapon's damage, rate, rounds, hit points and weight and, on a third line, its range, each special's effect (the Cup Holders spare the parts one hit in ten that gets past the armor; Heated Seats carry 10 % more rounds; the brakes only count in Instant Melee and network games, where the original reads them), and DEFENSE's armor and chassis cells. The numbers are read the way the game reads them (the part files, the simulation's own constants), so they are this game's. **A weapon's range** is how far its round goes on level ground from a car standing still, flown by the simulation's own step: a gun's, rocket's or missile's flight until its life runs out ("Range 490 m"; a guided missile's line adds how far it locks on, 650 m for a heat seeker, the radar's 600 m for a radar missile), where a mortar's shell comes down ("Lands 45 m out"; the EZK sets its own elevation, from level to 45 degrees, so it gives a span), a flame stream's reach ("Range 17-20 m": the roof mount tips the stream five degrees down into the ground, the side, bonnet and turret mounts carry it level), and "over 1 km" for the tank guns. A car's speed does not add to it (here a round leaves at the muzzle's speed alone: deviations.md, "Rounds' launch velocity"); the car's pitch and the lie of the ground do. Droppers say they are dropped behind, and the turret howitzer has no range (it pitches along its line to the target). Play Options' **Equip. Tooltips** turns them off (`[port] equipment_tips=false`; on by default); the menus' own tooltips stay.

**Ambient Occlusion, Shadow Detail, Anti-Aliasing.** **Ambient Occlusion** (World; Off, On\*) is the modern look's contact shadows under the cars, the shrubs and the rocks (SSAO); it is the costliest thing the modern look draws, because it makes every surface be drawn twice, and it is Off unless you turn it on (`[port] ambient_occlusion`, written when on; until it had a row, Shadow Detail High turned it on). **Shadow Detail** is the sun's shadows: Low (the default) to 600 m from the camera, High to 1500 m with finer near shadows, Off none; High costs about 6 % of the frame rate (T05 at 3440x1440 on a GTX 1080 Ti, 102 to 108 fps going to Low, docs/perf/plan.md). Round 5 made High the default; a settings file keeps whatever it says, so one saved by that build still says High (it cannot tell the default from a choice): set Low by hand for the frames. **Terrain Detail** High (the default since round 5) adds the ground's finest level near the car, about 1 ms a frame over Low at 3440x1440 (docs/perf/costs.md); a settings file still at the earlier Low default moves to High once, one chosen by hand otherwise is kept. **Anti-Aliasing** starts at 2x; 4x smooths a little more for about 3 % of a full-detail frame, and a settings file that already says 4x keeps it. **SMAA\*** and **2x+SMAA\*** (the modern look only) add Godot's SMAA, an edge filter run on the finished picture, alone or over 2x: it also smooths what multisampling leaves (the thin poles' crossarms, alpha-cut and shader edges), a touch softer, and costs one short pass (0.04 ms at 1920x1080 and 0.06 ms at 3440x1440 on an RTX 5090). In a slow pan past shrubs and telegraph poles SMAA alone flickers a little less than 2x and 2x+SMAA lands between 2x and 4x; 4x and 8x stay the smoothest. The settings file keeps the multisampling in its byte (Off or 2x) and writes `[port] screen_aa = "smaa"`, so an older build reads SMAA as Off and 2x+SMAA as 2x. The OpenGL renderer has no SMAA. **Shadow Detail Ultra\*** (the modern look only) is High with a shadow map twice as fine (8192), a softer filter, the near splits nearer and the splits blended: at a low sun a terrain shadow's edge tens to hundreds of metres out is a clean line where High draws a wide stippled band; at noon the two look alike. It costs about 0.25 ms more than High at 3440x1440 with Anti-Aliasing 8x and Render Scale 200 % on an RTX 5090 (about 4 %), under 0.15 ms at 1920x1080. The file keeps High in its byte and writes `[port] shadow_detail = "ultra"`, so an older build reads it as High. The modern look's ground also draws fewer of its layers far away (past 250 m no material scans, past 700 m no relief), a change nobody should see.

**Haze, Glow, Reflections.** Three rows change the modern look's air and light (Haze and Reflections on World, Glow on Effects); each is Off unless you choose it, Off draws nothing extra, and the 1997 look never shows them. **Haze** (Off, Light\*, Southwest\*; `[port] haze`, 1 or 2) adds air over the distance as in photographs of the desert: from 600 m out the ground, the mesas and the far mountains take on a little of the sky's horizon colour (blue-grey at noon, lilac at dusk, dark at night), Light about 5 % at 2 km and 16 % at 10 km, Southwest about 10 % and 27 %, on top of the haze the distant ring always had; it is one sum by distance for the map and the ring alike, so no band shows where the map ends, and at Visibility Range Far (the original's 600 m) it is not drawn. On an RTX 5090 at 3440x1440 with AA 8x and Render Scale 200 % its pass is about 0.07 ms (the frame about 0.25 ms more); at 1920x1080 it does not show in the measurement. **Glow** (Off, Lamps\*; `[port] glow`, 1) is a soft bloom round the brightest things only: muzzle flashes, explosions, fire and the lamps' glare, seen mostly at night; its threshold sits above what sunlit sand, paint, the sky and the dash reach (by day higher still), so a noon picture is unchanged unless a gun fires. At 3440x1440, AA 8x, Render Scale 200 % its pass is about 0.3 ms on an RTX 5090 (the frame 0.67 ms more); at 1920x1080 about 0.05 ms. **Reflections** (Off, On\*; `[port] reflections`, written when on) are screen-space reflections: glass, and the paint when Hood Gloss is turned up, show the cars, the road and the buildings on screen instead of only the sky. They need **Ambient Occlusion** On, whose normal pass they read: with it Off the row says *Needs AO* and keeps your choice for when it is On. Godot leaves surfaces rougher than 0.7 out, which is the ground, the roads and matte paint, so nothing on the ground looks wet. On top of Ambient Occlusion it costs about 0.44 ms at 3440x1440, AA 8x, Render Scale 200 % on an RTX 5090 (under the noise at 1920x1080), and in this game it shows little: the windows at a slant and a glossy car's roof. Mirrors draw none of the three's glow or reflections (their own picture is too small to show them).

**Terrain Shadows.** A modern-look row on World, On unless you turn it off (the 1997 look has none). **Terrain Shadows** (Off, On\*, Fine\*) bakes the hills', mesas' and canyon walls' own shadows on the land from the drawn ground and the mission's sun while the mission loads, so by day they are crisp, steady lines at every Shadow Detail, Off and Low included, from your wheels out to the map's edge; each edge is as soft as a real one, sharp at the foot of a rock and softer under a far ridge, and canyon floors, gullies and cliff feet are a little darker for the sky they cannot see. Without it the land's own shadows come from Shadow Detail's shadow map: to 600 m at Low and 1500 m at High, with a blurred or stepped edge at a low sun unless at Ultra. Cars, buildings and plants still cast their shadows through Shadow Detail (a car standing in a baked hill shadow past the shadow map's reach is lit). On bakes on a 2.5 m grid (under half a second on most maps, 8 MB of video memory on the largest), Fine on a 1.25 m grid (sharper small rocks and ledges; one to two seconds, up to 32 MB); the bake runs beside the loading and the shadows ease in when it is done. By day only; it costs about 0.1 ms a frame at 3440x1440 with Render Scale 200 % and nothing measurable at 1920x1080 (T05 at dusk on an RTX 5090; the same at On and Fine) (`[port] terrain_shadows`: `off`, `on` or `fine`, always written; a settings file without the key is On, so a file from before the row gets the shadows; Reset puts the row back to On).

**Lighting.** The first row on Effects, the modern look's (the 1997 look is the original's light whatever it says; `[port] lighting_calibration`, written when not 1997). **1997\*** (the default) lights each mission's ground and cars to the 1997 look's levels and colours, the frame through the 3D card's own curve and the sky in its painted colours. **1997 Sunlit\*** is the same calibration with the sun's strength solved too, by day: the ground keeps the 1997 look's contrast between its sunlit and its shaded faces, so sunlit ground, hills and cars stay bright while the shade stays dim, grey and cool under the sky's colours (a dusk such as T10's: the lilac and orange sky over a dark, low-chroma valley), the frame's mean still the 1997 look's; with 1997 Palette Grade on, the grade goes toward the mission's own 16-bit palette (the 3D card's colours, which keep a sunset sky's lilacs) instead of the software renderer's 256. **Filmic\*** is the calibration under a film-like curve with the modern sky's own colours, brighter and more saturated; **Off** the modern look's own light. No frame cost; applies at once (the calibration is solved again, from the bake cache when it has it). Since this build the sky's light on the scene is the share the calibration solves under every choice: before, the engine passed the sky's whole light (by day 3 to 10 times as much), which filled the shadows in (docs/deviations.md, "Lighting").

**Smoke Lighting, Heat Shimmer, Shimmer Strength.** Three of the modern look's rows on Effects, both Off unless you turn them on (the 1997 look has neither). **Smoke Lighting** (Off, On\*) lights the smoke and dust by the mission's sun and sky instead of one even light: the sun's colour follows its height (white at noon, warm low in the sky) and comes from its side, the far side takes the sky's colour, so smoke at dusk is warm toward the sun and dark away from it, and smoke at night is dim and blue instead of a bright grey (`[port] smoke_lighting`, written when on; no measurable frame cost). **Heat Shimmer** (Off, Fires\*, Fires + Road\*) makes the air wobble: Fires over fires, burning wrecks and flame streams, fading out by 260 m and never over anything nearer than the fire (your cockpit, a car in front); Fires + Road adds, on a hot day only (a day with the sun at least 30 degrees up over a warm desert palette, not on snow: not at dusk, dawn, late afternoon or night), a ripple on ground that runs nearly flat to your line of sight, far down the road (from 200 m out, full from 400 m: nothing near the car moves), strongest on smooth pavement (about half as strong on open flat ground, less on rough ground, none on plants, rock faces or ground you look at steeply, such as a rise ahead), and the road's mirage: far, level asphalt fading toward the sky's colour, wavering (on paved road only; nothing of the scenery is reflected in it). **Shimmer Strength** (Low\*, Medium\*, High\*, Extreme\*; `[port] heat_strength`, written when not Medium) sets how strongly the air bends, fire, road ripple and mirage together: Low is half of Medium, High 1.6 times it and Extreme 2.5 times; it applies at once in a mission and does nothing while Heat Shimmer is Off. The road ripple's nudge is an angle, so it looks the same size in a big window or at Render Scale 200 % as at 1920x1080 (it used to be a fixed 1.8 pixels of the 3D view, under a pixel on the screen at 3440x1440 and 200 %). The stock missions that are hot days at their own hour: T01, T03, T05, T08, T09, T11, T13, T14, T17, M01-M03, M06-M08, M10, M11, S02-S06 and A01 (T13's long straight road and T05's start show the road best); not T02, T04, T06, T07, T10, T12, T15, T16, M04, M05, M09, M12-M15, S01, S07. It is drawn in the main view only: the mirrors and the weapon camera stay still (`[port] heat_shimmer`: `fires` or `road`, written when not off). It costs nothing when Off or while nothing shimmers, and about 0.1 ms a frame while something does (T05 by a fire with the road in view at 3440x1440, Anti-Aliasing 8x, Render Scale 200 %, on an RTX 5090; 0.03 ms at 1920x1080).

**Clouds, Motion Blur.** Two of the modern look's rows on Effects, from upstream. **Clouds** (Flat, Volumetric\*; `[port] clouds`, `flat` or `volumetric`, Flat by default where upstream's is Volumetric; `I76_CLOUDS` for a run) is the modern sky's: Flat paints the mission's own sky texture's clouds on the dome, where the original paints them, with billows and light from the sun; Volumetric\* draws them as a layer of clouds standing in the world 1.5 km over the map (the same texture's clouds laid flat over the land, with depth, lit edges and haze far off), crossing the sky as fast as the original's. With Lighting at 1997 or 1997 Sunlit both take the sky texture's own colours. The 1997 look keeps the original's dome either way, and the Compatibility renderer draws Flat. Volumetric costs about 0.1 to 0.2 ms of the graphics card's time a frame over Flat (1920x1080, a GTX 1080 Ti, everything on: the frame rate within noise). **Motion Blur** (Off, On\*; `[port] motion_blur`; `I76_MOTION_BLUR` for a run) streaks what moves across the view over a fixed shutter of one 60 fps frame at any frame rate (your own turn and travel, other cars), while what travels with you (the cabin, the dash, the HUD, your car in the chase view) stays sharp; the original had none, so it is Off by default; Off costs nothing. Both apply at once and are not drawn in the 1997 look.

**Smoke Linger.** A modern-look row on Effects, Normal unless you choose Long (the 1997 look's smoke is always the original's). **Smoke Linger** (Normal, Long\*) decides what happens to a puff of smoke when its own life is over. Normal (the default) ends it as before. Long lets it hang on in the air: it keeps spreading, ever more slowly, its smoke spread thinner as it widens (twice the area, half the density), so it turns into a faint haze that drifts with the wind, rises less as it cools, and fades out only once it is all but invisible, about two and a half minutes after a lone puff's life (a thick column's, merged together, longer still); Long's smoke also starts denser and darker than Normal's, so a wreck's column is thick and black before it spreads into the haze, and a rocket's trail stays visible for half a minute or more; nothing vanishes at once. It applies to the damaged cars' smoke, the burning wrecks' (cars and scenery), the rockets' and the Ball O'Flame's trails, the explosions' smoke, and gives the mortar shells a thin trail of their own to leave hanging. Neighbouring haze puffs merge into fewer, wider ones, and when the haze would cover too much of the screen (several burning wrecks close by) the faintest of it fades out sooner, so the cost stays bounded: with seven smoking cars in view about 0.05 ms a frame at 1920x1080 on low settings and 0.2 to 0.4 ms at 3440x1440 with Render Scale 200 % (an RTX 5090); Normal costs nothing. The rear and door mirrors show the smoke behind you as the main view would if you turned round (the same smoke, haze and lighting), also when there is no smoke ahead of you. How black, dense and narrow the fresh smoke starts and how slowly the haze fades can be tuned live on the Developer panel (`smoke_start_dark`, `smoke_start_density`, `smoke_start_width`, `smoke_fade` below) (`[port] smoke_haze`, written when Long).

**Road Detail.** A modern-look row on World, Off unless you turn it on (the 1997 look has none). The roads are the original's road textures painted into the ground at 6.4 texels a metre (12.8 with a texture pack), so close up the asphalt is a soft, glossy smear next to ground drawn from photographed materials. **Road Detail** (Off, On\*, Strong\*; `[port] road_detail`, and `road_detail_strong` for Strong, each written when on) gives the paved roads a surface of their own, made in the shader with no textures of its own: aggregate grain and small exposed stones with their relief near the camera, fine cracks and darker sealed patches here and there, dark sealant lines along the lanes in stretches, broad lighter and darker stretches that break up the textures' repeat down a long straight, the edge lines', centre band's and yellow dashes' edges crisp and slightly chipped up close, the dirt strip beside the asphalt blended into the ground instead of ending in a hard edge, and the asphalt dry and matte rather than shiny. Where the traffic runs it leaves its average, not marks: two slightly lighter, smoother wheel paths in each lane and a darker oil-drip stripe between them, soft bands that fade to nothing across the lane, wander a little, come and go over tens of metres and grow heavier near junctions. At night the lane lines and dashes send your headlamps' light back toward you, as real road paint's glass beads do, so the road reads well past where the asphalt goes dark (only from behind the lamps: the chase view sees little of it), and the stones glint in the beams. **Strong** is the same with larger, rougher aggregate close up. The road's layout, colours and markings stay the original's; dirt roads are unchanged. Applied at once, but the lane bands from the next mission (they need a small bake of each road's direction as the map loads). Off draws nothing extra; On adds a few noise reads on the road's pixels.


**Visibility Range.** How far the world is drawn: **Far**, the original's 600 m with the sky's horizon beyond (the modern look fades the ground into the sky there), or **Max**\*, 20 km, so a map's far edges can be seen. Until you choose, it follows the look: Far in the 1997 look, Max\* in the modern one, and the row shows the look's (on the main menu the look the next mission starts in). A choice holds in both looks; Reset goes back to following the look. View only: the game's own ranges are unchanged. The original's row had Near (150 m), Med. and Far (both the mission's 600 m); the port has no Near. In shell.cfg it is `[port] draw_distance` (`0` Far, `1` Max, absent to follow the look).

**Screen Resolution.** Graphic Detail's **Screen Resolution** row (Display, on the main menu only) steps through Desktop (the game's borderless fullscreen at the desktop's size, as it starts) and the common window sizes that fit the screen; a size is a centred window, applied at once with no restart, and is kept for the next start. Alt+Enter still toggles fullscreen. A `--windowed`, `--fullscreen` or `--resolution` on the command line decides that start. Exclusive fullscreen is not offered.

**Show FPS.** Graphic Detail's Display page (the main menu's and the Esc menu's) has a **Show FPS** row: On draws a small counter in the window's top right corner, over the menus and the game, `64 fps  15.6 ms`: the frame rate averaged over the last second and the frame time that is, updated twice a second. Off by default, applied at once and kept in shell.cfg as `[port] dev_fps` (the Developer panel's Settings sets the same key).

**Frame rate on Graphic Detail.** Graphic Detail's last line, on the sheet and on its pages, says what frame rate the settings give. In a mission (the Esc menu's pads) it is measured: `Measured 84 fps (+12)`, the frames a second drawn behind the pad over the last second, read twice a second and again a quarter of a second after each change (the first frames after a change compile the new pipelines), with the change since the menu opened in brackets. In single player the game is paused under the menu, so the figure is the paused view's: the graphics card draws the same frame (the rear mirror keeps its every-second-frame redraw for it) but the game's own work stops, so play runs slower: on T05 at the defaults the line read 10-15 % over the play just before the menu, more where the processor is what holds the frame; the tooltip gives that play rate. In a network game the game runs on and the figure is play's. On the main menu, with no scene behind it, the line is an estimate: `Estimated ~95 fps`, your last mission's frame rate in the modern look (the median of its seconds past the first ten, kept with the settings and window size it ran at in `frame-rate.cfg` in the user folder) worked out for the settings on the sheet from what each costs on a test machine (docs/perf/plan.md, "Settings and the frame rate"); the window's size and Render Scale go by the pixels drawn. Measured against the estimate on T05 and T01 at seven combinations of the rows it was within 10 % (most within 2 %); it cannot know what else the machine is running. Before a mission it reads `Estimated: after a mission`; in the 1997 look it is blank. `[port] menu_fps=false` hides the line.

**Field of view.** Graphic Detail's **Field of View** row (Car & Cockpit, on the Esc menu's pad and the main menu's) sets how wide the main 3D views look. **Monitor**, the default and the recommended choice, keeps the original's height (73.7 degrees) and takes the width from your window's shape: a 4:3 window shows exactly the original's 90 degrees across, a 16:9 window about 106, so a wide screen sees more to the sides than the original did. The numbers are exact degrees across the window whatever its shape, 60 to 110 in steps of 5; **90** is the original's width (the pads mark the values the original game does not have with `*`, so 90 is the one width unmarked), which in a wide window means less height than the original had. A choice applies at once to the outside views and the cockpit's 3D view; the binoculars, the mirror and the radar keep their own framing. In shell.cfg it is `[port] fov_window` in degrees across the window (absent for Monitor). `[port] fov` is upstream's key for its own Field of View (Original, 80, 100, 110, degrees across a 4:3 view): the game writes it too, the nearest of those to your choice (left out when that is 90, so an older fork build, which read `fov` as degrees across the window, sees Monitor), so upstream's build reading the same shell.cfg sees about the same view, and reads it when `fov_window` is absent (a file of upstream's: 90 is Monitor, 80, 100 and 110 the same widths across the window). A file written by this fork before `fov_window` existed kept its widths across the window under `fov`; they move to `fov_window` unchanged.

**HD textures.** With a texture pack in the user folder's `tex-world-4x/`, `tex-world-3x/` or `tex-world-2x/` (side by side, each with a pack.json whose `scale` says its size; a `tex-world-8x/` beside the 4x may be partial, pack.json's `partial` and `covers`, see below; or the older plain `tex-world/`; or an art pack zip's `tex-world/` folder; the README says how to make one from your own install with `tools/upscale-textures.py`, whose `--families` runs each family of the cockpit's art through the model that suits it and gives the dials, needles and reticle the alpha step, their cut-out outline upscaled by 4xHDcube-Alpha so needles are straight and numerals round, and `tools/text-redraws.py` sets the smallest painted lettering again from free fonts: the dash's speedometer and tachometer figures, the damage panel's plate and labels, the licence plates, the police doors and the cars' name badges), the modern look draws its upscaled world, car and cockpit textures (the dash, gauges and panels among them); the 1997 look always draws the originals. Graphic Detail has two rows for it when a pack of any kind is found (with no pack there are none), each **1997** (the install's own textures, the original's, unmarked) or a size: **World Textures** (on World), 1997 or **4x**\* (the ground, the buildings, the props and the sky), and **Car & Dash Textures** (on Car & Cockpit), 1997, **4x**\* or **8x**\* (the cars, yours in the chase view too, with their dented stages, plates and badges, and the cockpit's own art: the dash, its gauges and needles, the panels, the hands, the mirror and the radar; 8x offered when a `tex-world-8x/` is beside the 4x). A 3x or 2x folder named in shell.cfg or on the Developer panel loads in the 4x's place and saves video memory and a second or so of loading but no frame time (docs/perf/costs.md); a plain `tex-world/`, a zip or a lone 3x or 2x folder loads as it is. **Partial packs and 8x.** A size's folder may hold only some textures: the game looks for each texture in its kind's size's folder and then in each smaller size's present, largest first, so an 8x pack of the cockpit and the cars (`tools/upscale-textures.py --scale 8 --covers "cockpit & cars"`, the README says how) is drawn over the 4x, which serves the world. A texture's kind: the cockpit's art is every texture whose name starts with `z` (the ones the pack tool keeps at full scale), a car's every texture of a vehicle's model as the game loads it, the world's the rest. **The difference.** 4x is what the modern look is made for, already finer than the screen at most distances; 8x is sharper only up close (the dash in front of you, a car at a few metres), for about 0.5 GB more video memory and no frame time: measured on a GTX 1080 Ti in T01 at 1280x960 (docs/perf/costs.md), the dash's 8x takes 482 MB more than its 4x and the cars' 54 to 79 MB (both together 510 MB), since the cockpit's art is drawn near full screen, so its textures are large, while a car's are small and only the cars in the scene are loaded. An earlier side-by-side at 3440x1440 and 1920x1080 could not tell them apart at play. **Defaults**, which Reset puts back: World Textures 4x and Car & Dash Textures 8x, where they fit: the 4x when `tex-world-4x/` is there and the graphics card has about 4 GB (3.8 GB) or more (else both 1997); the 8x when `tex-world-8x/` is beside it and the dash's half gigabyte fits, a card of 6 GB of video memory or more or an Apple-silicon Mac of 16 GB or more (the GPU shares the machine's memory), else the 4x; where the memory cannot be read (Linux) the 4x counts as fitting and the 8x is not picked. An 8x whose folder has gone loads the 4x. Both going to or from 1997 swaps the pictures at once (the cockpit's damage panel keeps its scale until the next mission); a size applies from the next mission. In shell.cfg they are `[port] world_textures` and `car_textures` (`1997`, `4x`, `8x`; any other whole multiple whose `tex-world-Nx/` folder is there still loads, shown as itself until the row is stepped). A file from before them keeps what it chose: `hd_textures=false` is 1997 for both (absent, Off if `hd_menu_art` is false, as before), and on, the world takes the 4x (or the 3x or 2x it named) and the cars and the dash one size from the two (`hd_dash_size` and `hd_car_size`, or the single `hd_texture_size` before them): the dash's 8x is kept, the cars' 8x alone is the 8x only where the dash's half gigabyte fits (a 4 GB laptop's dash 4x and cars 8x read as 4x, a 6 GB card's as 8x), else the larger of the two. The Developer panel's Settings has both keys, the 3x and 2x among their sizes. The menu pictures' pack has its own key, `hd_menu_art`.

**Hood gloss.** In the modern look the cars' paint, the cockpit's hood included, is clear-coated and mirrors the sky; Graphic Detail's **Hood Gloss** row (Car & Cockpit) sets how much, 0 to 100 in steps of 5: 0, shown as Matte, takes the coat and the sheen off, as the original's flat paint, so the cars show the original's colours; 5\*, the default since round 5, leaves a hint of sheen (a tenth of the way from Matte to Satin: the shader blends Matte's limits toward Satin's over 0 to 50); 50, Satin\*, softens the coat; 100, Gloss\*, is the full mirror; a level between shows as its number (35\*) and blends the two around it (live; the 1997 look is not affected). shell.cfg's `[port] hood_gloss` takes any whole number 0 to 100 (written when not 5; a file from when Matte was the default has no key and starts at 5), and the Developer panel has a slider over every level to sweep it live. A file from before it keeps its finish: `hood_finish=matte`, `satin` or `gloss` reads as 0, 50 or 100 (and the level is written from then on), an old `hood_matte=true` as Matte.

**Modern Physics.** Play Options' **Modern Physics** drives your car as a rigid body with suspension and tyres (Godot's Jolt engine) instead of the original's vehicle model; AI cars, weapons and damage are unchanged; not offered online. Off is the original's handling. See [docs/modern-physics.md](modern-physics.md).

**Play Options.** One list over the sheet's lines, which scrolls (the mouse wheel, Up and Down, Page Up and Page Down, or the pad past the first or last row): the original's check rows, Difficulty Level, then Hidden Wpns & Cars, Modern Physics, Simulation Rate, Checkpoints, Auto Reverse, Map Downloads, Unlim. Turrets, CB Voice, Check for Updates, Chase Crosshair, Load During Briefing, Turrets, and the fork's own: Unlim. Ordnance, Melee A.I., Equip. Tooltips, Solid Cliffs, Smart A.I., Skip Intro Movies. Force Feedback, Rumble Strength and the head-tracking rows are on Controls (below). The Esc menu's pad has the rows that apply in a mission: the check rows, Difficulty, Modern Physics, Simulation Rate, Checkpoints, Auto Reverse, Chase Crosshair, Load During Briefing, Turrets, Solid Cliffs, Smart A.I. and Skip Intro Movies.

**Turrets.** Play Options' **Turrets** row: how fast turrets turn toward their target (car turrets, gun emplacements, helicopters; yours and the AI's), as the 1998 build's (**1998**, the default: GOG's and the Nitro Pack's) or the 1997 CD's (**1997 CD**); the numbers are under `turret_slew` below. Nothing else differs: the arc (all the way round, the gun raised only for a target in front, to about 72 degrees), the aim ahead of a moving target, which weapons go on a turret mount and how many are the same in both. A network game plays its host's (the host form's Turrets). Until the merge with upstream this was `turret_slew` in `build-rules.cfg`; a line left there is no longer read. The row's help, the same on the host form:

> Turrets: how fast every turret turns to aim, yours and the enemy's. 1998 (GOG, Nitro Pack): half a turn in 1.8 s, and damage slows it by a quarter at most. 1997 CD: half a turn in 2.1 s, slower with every hit: at half health it cannot follow a car circling close by, and a wrecked one stands still. Online: the host's choice, and damage never slows a turret.

**Solid Cliffs.** A row of Play Options' list (the main menu's and the Esc menu's pad), Off (the default, the original's) or On\*; in shell.cfg `[port] solid_cliffs = "on"` (written only when on). Steep cliffs. In the original a car driven into a steep face can be lifted up it metres at a time, glitch up and down it, land on top or end inside it or on its roof. On, a face steeper than 60 degrees is a wall: your car stops at its foot and bounces off it with the knock a wall gives; slopes of 60 degrees or less climb as before. Computer cars driving freely meet the same walls; a computer car following one of the mission's scripted routes keeps the original's rule, so a route that climbs a cliff still works. Taken at the next mission start (a checkpoint or bug report state goes on under the rule it was made with). Online it is the host's, in melee and co-op games.

**Smart A.I.** A row of Play Options' list (the main menu's and the Esc menu's pad), the fork's own: Off (the default, the original's AI), On\* (every behaviour below) or Custom\* (some of them: the Developer panel's Settings has a Smart A.I. check box for each, so one can be tried alone; the row's click goes from Custom to Off). A change in a mission applies from the next mission start: the rule is part of the session's build, and a mission started with it logs "smarter opponents: " and the behaviours. In shell.cfg it is `[port] smart_ai`, which the row writes: left out for Off, `"all"` for On, the behaviours' names for Custom. By hand it takes empty (off), `"t"`\*, `"n"`\*, `"g"`\*, `"d"`\*, `"all"`\*, a list such as `"gun_lay,settle,unstick"`\*, or a number; write it in quotes (`I76_SMART_AI`, docs/dev-hooks.md, wins over it). Smarter opponents (docs/deviations.md): the computer cars get behaviours the original's do not have. `t` lines up the guns (gun_lay: the nose swings onto you when you are in range, so their fixed guns land against a moving car; settle: the first burst comes a beat after the nose is on, a reaction time, 0.2 s at the best skill to 0.4 s at the worst). `n` is the terrain group (hill_pursuit: they climb to you instead of creeping below you; with any of the terrain behaviours a chase re-aims at you as you drive on, and a car held back by the caution (on a mesa above you, say) gives it up for a while and comes down as the original's would; climb_probe: gentle and side slopes no longer read as walls; ledge_caution: they brake for a cliff's edge (a drop of 10 m or more) or a crest they would fly off rather than going over it, and will not back over one, but drive down banks and over bumps as the original's do; unstick: a wedged car backs out on an arc toward you and tries another line). `g` (positions): cars waiting their turn while others attack you spread round your rear quarters and flanks, out of your gun cone, instead of running back and forth. `d` (drop_chased: a car you are tailing lays its mines or oil in front of you and holds its line; rear_guns: a car with a rear gun keeps you behind it so the gun has a shot). Only the computer cars' decisions change, never their grip, power or armour, and only while they are fighting: a mission's scripted drives, escorts and races are the original's. The fighting behaviours (`t`, `g`, `d`) are used only on you (and your co-op teammates): a computer car going for the van you escort, the building you defend, your wingman or another computer car fights it as the original's, so enemies do not kill what you protect more efficiently and allies do not win the mission for you. In a melee (Auto Melee or online) they are smart against everyone, each other included; the scenarios (the stock ones and the remixes) are missions and keep them on you. The terrain group drives better whoever the target is (in T10 the cops the original's AI loses off the mesa's edge mostly survive and come for the van: expect it to take more fire). `any_target`\* (a Developer panel box; `"everything"`\* is every behaviour with it) brings back the first Smart A.I., every behaviour against any target. It is part of a checkpoint's or a bookmark's state: a checkpoint retried plays by the rule it was taken with. Online it is the host's (the server runs the computer cars).

**Unlim. Ordnance.** A row of Play Options' scrolling list, after upstream's rows: the original keeps at most 160 live rounds of a kind (40 online for mines, caltrops, Blox and fire drops) and removes the oldest past that; on, there is no cap, so a long oil or fire trail stays whole. Single-player games only: a network game keeps the original's cap for everyone.

**HiFi Audio.** With a sound pack installed, Audio Control (the main menu's and the Esc menu's) has a **HiFi Audio** row under Output and LFE Level: On (the default) plays the pack's sounds and movie tracks in place of the original's, Off the original's; sounds and movies started after a change follow it. The pack's name is in the row's tooltip. Without a pack there is no row. In shell.cfg it is `[port] hd_sounds` (written when off).

**Output and LFE Level.** Audio Control (the main menu's and the Esc menu's) has two rows of the port's own. **LFE Level** (0 to 200 %, 0 the default) turns on a bass-shaker signal of the port's own and sets its level: the engine as a sine by rpm, the road as a rumble by surface (low and lumpy off the roads, higher and gritty on a dirt road, a faint smooth hum on asphalt, a knock as each wheel crosses onto or off a road or a bridge, and never quite the same twice: each mission draws its own randomness) and the car's speed, engine or no engine, stronger with the load on the springs (a hard turn, a stop) and with their movement over bumps, a thump per shot, per hit (by its damage, a crash the strongest thing there is, and a ram or a crash ringing the cabin for about a second and a half after, as the original's cockpit view jolts) and per explosion, all 15 to 90 Hz under a limiter; each of these sources has a level of its own in `shell.cfg` (`lfe_engine`, `lfe_road`, `lfe_hits`, `lfe_shots`, `lfe_explosions`, `lfe_offroad`, `lfe_bumps`, below) and a slider on the Developer panel (100 % is 1.5 times the synth's own level, 200 % three times; the signal has its own limiter after the level, so no setting clips it: a pile of thumps rounds off under it rather than leaning on the master limiter). At 0 nothing is added and every output plays as the original does. **Output** says where the signal goes: Stereo (the default) and Phones (the same: neither Godot nor the game has anything headphone-specific) mix it into both channels and boost the effects' own bass under the crossover (`crossover`, 90 Hz) by the level's share (100 %: twice, +6 dB well under the crossover; the boosted effects share the master limiter with the rest of the mix), for a sub or bass shaker fed from the stereo output, or whatever your rig does with the low end; **5.1**\* and **7.1**\* put the signal on the LFE channel alone, for a shaker on a receiver's or interface's sub output (the two are the same: the LFE of whatever surround layout the device has; with a stereo device nothing plays). The game cannot change the device's channels: the system's sound settings do. Explosions are felt by distance: full within 15 m, falling as 1/r (the air blast) to 120 m and as 1/√r (the ground's wave) beyond, lower and longer, to nothing at 2 km. In 5.1 the LFE also carries the game's own sounds: Godot sends every positional sound there at full level. A file from before these rows with `tactile = lfe` reads as 5.1, and one with Output 2.1 (an earlier name for the stereo mix) as Stereo; a file that chose 2.1, 5.1 or 7.1 without an LFE Level keeps 100 %, the default then. The Developer panel shows the output and the signal's peak.

**The port's values.** On the pads (the main menu's sheets and the Esc menu's), every row that offers the original game's value marks each value the original does not have with `*`; the unmarked value is the original's. Field of View: every value but 90 (Monitor\* included); Force Feedback: Pad Enhanced\* and Wheel\* (the original drove a force-feedback stick, never a wheel); Melee A.I.: Difficulty\*, Easy\*, Hard\*; Solid Cliffs: On\*; Smart A.I.: On\* and Custom\*; Hood Gloss: every level but Matte (0, the original's flat paint); Render Scale: every value but 100 %; Anti-Aliasing: 8x\*, SMAA\* and 2x+SMAA\*; Shadow Detail: Ultra\*; Visibility Range: Max\*; World Textures and Car & Dash Textures: 4x\* and 8x\* (1997, the install's own textures, is the original's); Ambient Occlusion: On\*; 1997 Mode: Off\* (the modern look); Crash Blur: Off\*; Vegetation: Low\* and High\*; Mouse Camera: Slow\*, Normal\*, Fast\*; 3D Garage: On\*; Head Tracking: Analog\* and Digital\*; Rumble Strength: every value but 100 %. Defaults are not marked: a row starts where the port thinks best (Car & Dash Textures at 8x\*, Hood Gloss at 5\*), and the tooltip says which value was the original's. A row without a mark (Max FPS, VSync, Renderer, Simulation Rate, ...) has no original's value to tell apart.

### Controls

Options > **Controls** (the original's Control Configuration's place on the Options Menu, and the in-mission Esc menu's
Controls) is a sheet of the port's: **Force Feedback**, **Rumble Strength** and **Wheel Strength** (Play Options' until round 5),
**Head Tracking**, **Head Track Sens.**, **Head Track Reach**, **Head Track Centre**, **Opentrack**, **Opentrack Auto** and **Opentrack Profile** (Head tracking, below; in a
mission a change takes effect at once), then **Mouse Options...** and **Key Map...**, each a screen that comes back to it. The key map is the original's Control
Configuration screen (its keys, the mouse's buttons, and Calibrate for a pad); it also opens Mouse Options. Mouse Options holds the
mouse's settings: Mouse Camera (the F2 chase view), Mouse Sensitivity, Invert Y Axis, Cockpit Mouse Look, Camera
Return, View Zoom Reset, Mouse In Window, the bindings of the five mouse buttons (the two side buttons
included) and what the wheel does (View Zoom or Cycle Weapon). Chase Crosshair, an aiming mark in the F2 chase view
for keyboard, pad and mouse alike, is in Play Options (the last row of the shell sheet's scrolling list, and the in-mission Esc menu's
Play Options); in a network game it shows only if the host allows it. In the modern look the cockpit's gunsight ring and
the chase crosshair are drawn as smooth vector shapes at your window's resolution; `[port] crosshair_drawn=false` in shell.cfg brings back
the game's sprite ring and the snapped bars.

**Keyboard Steering Assist** (Play Options, the last row; the in-mission Esc menu's Play Options too; on unless you turn
it off): a held steer key eases the wheels in quickly instead of the original's slow ramp (√(t/3) of full lock by the time
held, full lock after 3 s, which runs wide in sharp turns), keeps a short press inside the tyres' grip and to a sane
cornering force (so corrections do not squeal or twitch; a key held past 0.6 s gets the whole lock), and steers into a
slide by itself, so a car that has stepped out comes back in line with no key held. Off is the original's ramp. The
throttle keys are the original's either way, and a pad is unaffected.

**Auto Reverse.** Off by default (Play Options' Auto Reverse row, in the shell and the in-mission Esc menu): hold the
brake on a stopped car and it shifts into reverse and backs up; hold accelerate while backing up and it brakes, then
shifts to drive. A pad's triggers work the same. Off, reverse is the original's own key (X) and the brake only brakes.

Shift or Ctrl held cancels a command, as in the original. Port keys: C poetry (in network games, the CB radio's push-to-talk), Ctrl+F3 debug text, Ctrl+F7
Modern Physics, Ctrl+F5 debug fly camera (right mouse looks, WASD/QE fly, Shift for speed), Ctrl+F9 wins the trip
mission on the spot (debug), Ctrl+F2 or Ctrl+` the Developer panel when it is turned on (`developer=true` under `[port]` in shell.cfg; docs/dev-hooks.md).

**Co-op starts.** In a co-op game the mission starts for everyone together, once every player's game has loaded it. While it waits, the
players already in it see PLEASE STAND BY with who is still loading or watching the briefing; after two minutes it starts without them
and they join in when they are ready. Each player's briefing plays once their mission has loaded; when everyone has loaded and
anyone skips theirs (Esc), the briefing ends for everyone. A won mission goes on by itself to the trip's next mission with everyone
in the same cars (MISSION COMPLETE, "Next mission: ... in 15 s"); the host's Esc menu has Next Mission (now) and Back to Lobby
(everyone back to the game's lobby, still ready). After the trip's last mission the group is back in the lobby. After a failed mission
the host chooses on the end menu: Replay Mission (everyone again from the start), Back to Lobby, Leave Match (back to the menus) or
Exit I76 (back to the desktop); the others see that the host is choosing. The host's Esc menu has Replay Mission and Back to Lobby
during the mission as well. In the host form's co-op list, and on the lobby's mission line, the pointer on a mission shows what it is
about (its first objective). In the lobby the host's GAME SETUP button (or S) opens the host form again: pick another mission, change
Extra Enemies, Damage Taken, No. Drivers, Invite Only, Hidden Cars, Car Reset, CB Radio, Turrets, the game's name or password, and APPLY;
everyone stays in the lobby, sees the new mission and a line for each change in the chat, and the next START plays it. Sim Rate stays as
the game was hosted. A player whose car the new rules refuse is put in the mission's own car and told why.

**CB voice.** In network games the CB radio sends your voice while you hold the poetry key (C). Sending needs a
microphone, and the game does not open the audio input (so no system asks for microphone access) until you pick one:
CB Microphone, in Audio Control (front end or in a network game), starts on None; choose Default or a device and talk.
With None the key only says, once a session, to choose a microphone. Hearing the other players needs nothing. On macOS the
microphone works from the next start after you pick it (macOS asks for access then).

**Cheats.** The original's words, typed while holding Ctrl+Shift (single player): `getdown` stops the mission script
and sets everyone on you; get killed (or Ctrl+Del) and the mission counts as won 5 s later, the original's level
skip. `flflat`, `frflat`, `blflat` and `brflat` blow one of your tyres. `wiggleburger` turns a double-vision wobble
on or off. `freelance` and `thirdnostril` do nothing, in the original too. None of them marks you as a cheater.

**Game pads.** A pad is the original's joystick 1: the left stick steers, the right trigger accelerates and the
left brakes, the right stick swings the camera (and is a head look in the car), A fires, RB is the handbrake, B cycles, X and Y
target, the D-pad links, reverses and changes target. LB is a shift: held, A fires the rear hardpoint (3), B the dropper (4), X and Y
hardpoints 1 and 2, L3 and R3 specials 1 and 2, and the D-pad is binoculars (up), radar range (down) and the gears (left down, right up). Start opens the game menu and, in a network game, holding Back (View) shows the standings; bind Start or Back to a
command on the Controller screen and they do only that command instead. The pad also drives every menu
(D-pad or left stick to move, A to click, B and Start to go back); A, B or Start skips a movie, and B or Start a
skippable cut-scene, as Esc does. Everything is rebindable on the Controller
screen (Controls > Key Map > Calibrate).

**Head tracking.** [opentrack](https://github.com/opentrack/opentrack) (a webcam, a phone, a TrackIR-style clip) can turn
your head in the car. The game reads either of two opentrack outputs, whichever is sending: **freetrack 2.0 Enhanced** (opentrack's
default profile, the one TrackIR-style games read; Windows only) or **UDP over network** (settings **127.0.0.1** port **4242**;
any system). Press Start in opentrack; then set Options > Controls > Head Tracking (also on the Esc menu's Controls) to **Analog** (the view follows your head) or **Digital** (turning past a
threshold glances left, right or down at the dash, or turned right round looks out of the back, as the glance keys do). Three rows
shape Analog: **Head Track Reach** is how far round the view goes at your full head turn (80, 120, 160 or **180**: straight out of
the rear window; 160 is the original's own look rear); **Head Track Sens.** sets that full turn, reach ÷ sensitivity past the
still zone (**7**: about 26° of head looks right behind you; at 180 a 19° turn looks 90° round); **Head Track Centre** is a still
zone round straight ahead and a softer curve out of it, so small head movements leave the view dead ahead and a bigger turn
swings it round: **Snap** (the default: 1.7°, a 1.7 power curve, as the opentrack layer for the original game had), Light (1°,
1.4), Strong (3°, 2.2) or Off (in proportion). The zone is subtracted, so the view never jumps as you leave it. Nodding moves the
view about 3° a degree whatever the reach, and as you look round past 90° the view lifts to the look rear's level. Off at
reach 80 and sensitivity 3 is the head tracking of earlier versions, which a sensitivity saved by them keeps. The glance keys and the pad's right stick win while held;
when opentrack stops the view eases back ahead. If the view turns the wrong way, invert that axis in opentrack's Options > Output.
Analog needs the 3D dash (F1). Both outputs give the same angles: FreeTrack's shared memory (FT_SharedMem) holds radians with yaw
and pitch the other way round and millimetres, which the game turns back into the UDP output's degrees and centimetres, so a
profile that turns the view right over UDP does so over FreeTrack too. shell.cfg `[port]`: `head_track` (off / analog / digital), `head_track_sensitivity` (7), `head_track_reach` (180), `head_track_centre`
(snap),
`head_track_port` (4242), `head_track_bind` (127.0.0.1; 0.0.0.0 to take a tracker on another machine) and
`head_track_position` (true moves the eye with your head, up to 10 cm; off) and `head_track_source` (`auto`, the default: the
output that is sending, and while both are, the one already in use; `udp` or `freetrack`: that one only).

**Starting opentrack from the game.** Under Head Track Sens., the Controls sheet has three rows for opentrack. **Opentrack** shows
its state: Missing (the game cannot find it), Stopped, Running, or Tracking (poses are arriving over UDP or FreeTrack; a tracker
on another machine counts too); a click when Stopped starts it. **Opentrack Auto** (`[port] opentrack_auto`, off): a mission with Head
Tracking on starts opentrack when none is running and nothing is arriving, and when the game exits it closes the opentrack it
started; an opentrack you started yourself is never closed. **Opentrack Profile**: a click writes `I26.ini` into opentrack's
profiles (the neuralnet webcam face tracker, no markers needed, sending UDP to 127.0.0.1 on `head_track_port`); it never writes
over a file of that name, and says No folder until opentrack has made its profile folder (Documents/opentrack-2.3; the
`ini` folder beside a portable opentrack; on Linux also ~/.config/opentrack-2.3). The game looks for opentrack in Program Files,
Program Files (x86) and the per-user Programs folder on Windows, /Applications and ~/Applications on macOS, on PATH, and on
Linux in /usr/local/bin, /usr/bin, /opt/opentrack/bin and ~/.local/bin; `[port] opentrack_path` names it anywhere else (the
program, its folder or its .app).

On Windows the profile is not needed: opentrack's default profile, with its FreeTrack output, works as it is (the same profile
the original game's head-look tools read). opentrack has no command-line switch or setting that starts tracking when it opens, so once, by hand: choose the I26 profile (or your own)
in opentrack's profile list, open the tracker's settings (the hammer) and pick your camera, and then either press Start each
time, bind a key to Start Tracking in Options > Shortcuts, or (the hands-free way) add the game's program in Options > Game
detection with the I26 profile and tick its box: opentrack then starts tracking by itself while that program runs and stops when
it exits. The program's name is the one in Task Manager: `i26.exe` for a release, the Godot executable's name for a
development build (which every Godot game shares). macOS: there is no official opentrack build for the Mac; community builds
run, and the game starts one in /Applications like any other, but which trackers they carry (and the camera permission they
need) is theirs; the UDP output works the same.

**Rumble.** A pad's rumble follows the game's own force-feedback effects: Controls' Force Feedback row steps Off, Pad (those
effects only, the original's and the default), Pad Enhanced\* (and short pulses for a nitrous kick, the handbrake, gear changes,
the starter, each kind of weapon's shot and a light engine growl) and Wheel (Windows). Controls' Rumble
Strength sets 25 to 150 % on every level sent to the pad. Both apply when a mission starts, and from the Esc menu at once.

**Briefings while loading.** In the modern look a mission's briefing plays while the mission loads (Play Options' Load
During Briefing, after Chase Crosshair in its list; on by default): the loading card shows first for a few seconds (the mission
already loading behind it), then the briefing, and a briefing watched to its end goes straight into the mission. While
"PLEASE STAND BY . . ." shows faint in the movie's corner the mission is still loading and the briefing cannot be skipped (a
press then is not saved up either); once the world is built a press skips it, and the loading card comes back with PLEASE STAND
BY in its corner until the mission is ready (a briefing that ends before the load gives way to the card the same way). A thin
line under PLEASE STAND BY fills from left to right as the mission loads, full when it is loaded; every other start
(melee, instant action, a bookmark, a network game, the 1997 look) shows the same line on its loading card. The line says READY only when
the mission is ready: a press then starts it at once. Off, and always in the 1997 look (the row is grey on the
Esc menu's pad and shows no check in the shell's list there), the mission loads behind the card first and the briefing
plays after, as in the original.

**Joysticks.** A flight stick, wheel or any other USB device that is not a game pad is found too (it is joystick 1 when
there is no game pad). Out of the box the stick steers sideways and accelerates (forward) or brakes (back), the trigger
fires, buttons 2 to 10 cycle, target, brake, link, map, horn, view and reverse, and the hat looks. Calibrate opens the
Joystick Configuration screen: move an axis or press a button and its row appears and lights, click it to choose what
it does; any axis can be the throttle, the steering or the camera, Invert turns it round, and the dead zone is set there
(a throttle lever or twist is just another axis). See [docs/joystick.md](joystick.md).

Without `--mission` the game plays the intro and opening credits (Esc, Space, Enter or a click skips), then opens
the original front end; Play Options' Skip Intro Movies (off by default) leaves those two out at every start, and only those
(briefings, outros and cut-scenes still play), while `--skip-movies` leaves out every movie. Useful options (after `--` when run through Godot):
`--install DIR`, `--mission a01`, `--drive [car.vcf]`, `--melee`, `--1997`, `--cockpit`, `--windowed` (Godot's, before the `--`).
For unattended runs `--skip-cutscenes` skips a mission's skippable camera scenes as Esc would, and `--mute` turns the sound off.

**Another language's voices.** The port ships no game files, but it can read yours: copy the voice files of a dub you own (the 1997
German one from your own disc, say) into a folder `voices/de` in the user folder (`%LOCALAPPDATA%/I26` on Windows) and start with
`--voices de`, or give the folder itself (`--voices D:/mydub`). Those sound files play in place of the install's files of the same
name, and the mission scripts wait for their lengths. Without `--voices` nothing changes; `--voices en` is the same.

**Your own music.** Songs you own (.mp3 or .ogg) in a folder `music-extra` in the user folder (`%LOCALAPPDATA%/I26` on Windows),
or in the folder `--music-extra FOLDER` names, are mixed into the mission music: one song start in three plays one of them, in
shuffled order, in place of the disc track, and the disc's tracks go on after it. `I76_MUSIC_EXTRA_EVERY=N` (1 to 20) changes the
three; `--music-extra off` turns it off for a run. The menus' music is not touched. Nothing is shipped with the port.

### Steam Deck

I26 runs on a Steam Deck as the Linux build. What is written here comes from the notes of a Deck test of the same games and
the checklist for I26's own; whatever has not been run on a Deck with I26 yet says **to be confirmed**.

1. **Install.** Unpack `i26-<version>-linux.zip` in Desktop Mode (for example into `~/i26`) and give it the game as under
   *Installing and starting* above (a GOG installer next to `i26.x86_64`, or a game folder copied in). In Steam choose
   *Add a Non-Steam Game* and pick `i26.x86_64`; a game folder somewhere else goes into the launch options as
   `-- --install /path/to/Interstate76`. `tools/deck/add-to-steam.py` does the same from a terminal (with Steam shut down), makes a plain library tile
   and offers the controller layout below; see `tools/deck/README.txt`. No Proton: this is the native build (the Windows build under Proton
   also starts from a non-Steam entry with Proton forced, but is not what is described here).
2. **Pad.** In Game Mode Steam Input presents the Deck's controls as an Xbox-style pad (the test notes saw it as a virtual
   Xbox 360 pad). I26's default pad map should apply as written under *Game pads* above (left stick steers, triggers accelerate and brake, A and RB fire, B cycles, ...) and the
   Controller screen should rebind it; both are to be confirmed on a Deck. The layout in `tools/deck/` keeps the pad as an
   Xbox pad and adds hardpoints 1 to 5 on the left trackpad as a radial menu, the right trackpad as the menu pointer (press to click),
   and on the back grips L4 the emergency brake and R4, L5 and R5 Use Special 1, 2 and 3.
3. **Picture.** The Deck's panel is 1280x800. The game draws 16:9 (the project's 1280x720 base) and the front end keeps the
   original's 4:3 frame, so some bars are expected; to be confirmed on a Deck.
4. **Rumble.** The Deck's own controls are wired, so the rate limit that keeps a Bluetooth pad's rumble from stalling the game has little to do there. Whether Steam turns
   I26's rumble into the Deck's haptics is to be confirmed; Steam's rumble intensity is set in the game's controller settings.
   Do not switch Steam Input off for the entry, or the pad is not presented to the game.
5. **Text entry** (a bookmark's name, the multiplayer name): Steam's on-screen keyboard comes up with Steam + X. I26 does not open it by itself (to be confirmed).
6. **Docked to a TV.** In Game Mode Steam gives a game 1280x800 when docked unless the entry's *Properties > General > Game Resolution* is
   set to Native or to 1920x1080; with the default the picture is scaled onto a 16:9 TV with bars (observed with the original
   game under Steam's compositor; to be confirmed with I26). A TV that looks too dark: Graphic Detail's **Monitor Brightness** row. If the picture is
   wrong or the game does not start, Graphic Detail's **Renderer** row (Vulkan, OpenGL) takes effect at the next start;
   Vulkan is expected on the Deck (to be confirmed).
